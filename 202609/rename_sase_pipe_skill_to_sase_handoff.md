# Rename the `/sase_pipe` skill to `/sase_handoff`

## Goal

Rename the bundled `sase_pipe` xprompt skill to `sase_handoff`, so coding agents invoke
it as `/sase_handoff` (and inline as `#skill/sase_handoff`). Update every reference to
the skill across source, tests, docs, and SASE memory. Afterward, the only `sase_pipe`
strings left in the sase repo should be the intentionally retained `.sase_pipe_pending`
runner marker (see Out Of Scope).

## Scope Decision (Please Confirm At Approval)

This plan renames the **skill** only. The CLI command it wraps stays `sase pipe`,
because that is the literal command the skill teaches. The same goes for the
`max_agent_pipe_chain` config field, the `.sase_pipe_pending` handoff marker, and the
Python internals (`pipe_handler.py`, `run_agent_exec_pipe.py`, `PIPE_PENDING_MARKER`,
`pipe_depth`, `piped_from`). This matches how the other handoff skills work:
`/sase_plan` wraps `sase plan propose`, `/sase_monitor` wraps `sase monitor start`, and
`/sase_questions` wraps `sase questions`.

Renaming the `sase pipe` command itself (to `sase handoff`) is a much larger change with
compatibility risk. It would touch the CLI parser and registry, `docs/cli.md`, config
schema and defaults, `sase/sase.yml`, the runner marker protocol used by in-flight
agents, and possibly persisted agent metadata keys. If you want that too, send it back
as plan feedback and it will be replanned as an epic.

## Steps

### 1. Rename and reword the skill source

- `git mv src/sase/xprompts/skills/sase_pipe.md src/sase/xprompts/skills/sase_handoff.md`.
- In the frontmatter, set `name: sase_handoff`. Keep `skill: true` and
  `log_skill_use: false` as they are.
- Update the frontmatter `description` so handoff is the primary verb and "pipe" is
  still accepted as a trigger word. For example, change "Use ONLY when the user
  explicitly asks you to pipe or hand off work to another agent" to "Use ONLY when the
  user explicitly asks you to hand off (or pipe) work to another agent". Leave the rest
  of the description as it is.
- Reword the body's skill-level prose from "pipe" to "hand off". Every literal CLI token
  stays unchanged: `sase pipe ...`, flags, and `max_agent_pipe_chain`.
  - Core Rule: "asks you to pipe or hand off work" → "asks you to hand off (or pipe)
    work". "so run the pipe command in the foreground" → "so run `sase pipe` in the
    foreground". "inside the piped prompt itself" → "inside the handoff prompt itself".
  - Heading `## When To Pipe` → `## When To Hand Off`.
  - "Do not pipe for:" → "Do not hand off for:".
  - Hazards: "The piped prompt is re-parsed by the successor" → "The handoff prompt is
    re-parsed by the successor". "so the piped prompt needs no workspace reference" →
    "so the handoff prompt needs no workspace reference". "a piped successor that pipes
    again can eventually be refused" → "a successor that hands off again can eventually
    be refused".
  - Leave the Canonical Invocation block (`sase pipe 'implement the approved plan' ...`)
    and the Options list exactly as they are.

### 2. Update the skill source test

In `tests/main/test_init_skills_sources.py`:

- Rename the parametrize case key `"sase_pipe"` → `"sase_handoff"`.
- Update the expected phrases changed by Step 1: `"Do not pipe for"` →
  `"Do not hand off for"`, and `"The piped prompt is re-parsed by the successor"` →
  `"The handoff prompt is re-parsed by the successor"`. Keep every other phrase (the
  `sase pipe ...` invocation, `max_agent_pipe_chain`, the option flags, and so on). They
  should still match unchanged text.
- Add a small regression test in the same file asserting that the packaged skills (via
  `load_skills_from_package()` or `get_sase_package_skills_dir()`, both already
  imported) include `sase_handoff` and no longer include `sase_pipe`. This keeps the old
  name from quietly coming back. Match the style of the existing tests in that file.

### 3. Update docs

- `docs/xprompt.md` bundled-skills table: delete the `sase_pipe` row. Add a
  `sase_handoff` row in alphabetical position, between `sase_git_commit` and
  `sase_memory_read`, keeping the purpose text "Hand this agent's turn to the next
  session member with `sase pipe`". Keep the table's column alignment (`just fmt` /
  Prettier will realign it).
- `docs/cli.md` (~line 608): "see the `/sase_pipe` skill" → "see the `/sase_handoff`
  skill". Leave the `sase pipe PROMPT` command row unchanged.
- `docs/monitors.md`: "(the `/sase_pipe` skill)" → "(the `/sase_handoff` skill)" (~line
  823), and "See the `/sase_pipe` skill" → "See the `/sase_handoff` skill" (~line 849).
  Leave the "Pipe vs. monitor" heading and its anchor (`#pipe-vs-monitor`) as they are.
  They describe the `sase pipe` command, and other docs link to that anchor.

### 4. Update SASE memory (user-authorized by "update ALL references")

These are mechanical name updates inside accepted decision records. The claim,
rationale, cost, and reopen conditions do not change, so no supersession is needed.
Follow the `/sase_memory_write` "Edit And Republish" flow:

- `sase/memory/decisions/gates-never-block.md`: "`sase monitor` and `/sase_pipe`" →
  "`sase monitor` and `/sase_handoff`".
- `sase/memory/decisions/host-owned-completion.md`: "(`/sase_plan`, `/sase_monitor`,
  `/sase_pipe`, `/sase_questions`)" → "(`/sase_plan`, `/sase_monitor`, `/sase_handoff`,
  `/sase_questions`)".
- `sase/memory/decisions/single-turn-agents.md`: "`sase monitor`, `/sase_pipe`,
  `/sase_plan`, `/sase_questions`" → "`sase monitor`, `/sase_handoff`, `/sase_plan`,
  `/sase_questions`".
- Re-wrap the edited paragraphs if line lengths change (the memory notes are formatted
  by `just fmt`). Then run `sase memory init` to regenerate `AGENTS.md`, the provider
  shims, and the memory README. The decision roster renders only titles and
  descriptions, so this may produce no diff. Commit whatever it does produce.
- Do **not** change prose that says "plan, monitor, pipe, or questions handoff". That
  wording appears in `src/sase/xprompts/skills/sase_final.md`,
  `src/sase/main/init_memory/templates/memory-sase.template.md`, generated
  `sase/memory/sase.md`, and `sase/memory/xprompts.md`, and it names the `sase pipe`

- Do not touch the `chezmoi` linked repo in this turn (see Step 6).

### 6. Generated skill deployment (post-landing, not in this turn)

Per the generated-skills memory, the chezmoi copies must only be deployed from a landed,
clean source revision. The implementing agent should only preview:

- Run `sase skill init --dry-run` (or `--diff`), which is read-only. Confirm it plans to
  add `sase_handoff/SKILL.md` for every provider and to retire/delete the
  `sase_pipe/SKILL.md` copies.

After the change lands on `master`, the user (or a follow-up agent) runs
`sase skill init --force` from a clean, merged tree, then `chezmoi apply` if it was
skipped. `--force` deletes the retired `sase_pipe` copies in all seven provider
directories and rewrites `home/.sase-skills-manifest.json`. Until that deploy runs, live
agents keep seeing `/sase_pipe`. Put this reminder in the final response.
