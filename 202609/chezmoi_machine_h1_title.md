# Chezmoi-Templated Machine-Specific `memory.h1_title`

## Problem

Bryan's home-level agent instructions (`~/AGENTS.md` plus the `CLAUDE.md` / `GEMINI.md`
/ `QWEN.md` / `OPENCODE.md` provider shims) are generated by `sase memory init` into the
chezmoi home source root (`~/.local/share/chezmoi/home`, because `use_chezmoi: true`)
and deployed by chezmoi to every machine. The H1 title comes from `memory.h1_title`,
which today is resolved by globbing `dot_config/sase/sase.yml` + `sase_*.yml` with
last-declared-wins and no machine awareness (`_load_user_amd_h1_title` in
`src/sase/amd/_config.py`).

In the real chezmoi source, `sase_athena.yml` declares
`memory.h1_title: "athena - Bryan Bugyi's Home Server"` while `sase_apollo.yml` and
`sase_kellys_mbp.yml` declare only `id:` blocks. Because the generated files are plain
(non-template) chezmoi source files, **every** machine — including apollo and Kelly's
MBP — deploys a home `AGENTS.md` titled "athena - Bryan Bugyi's Home Server". Worse, if
another machine overlay ever declares `memory.h1_title`, the alphabetically-last overlay
would win for all machines.

Goal (first increment of chezmoi support for machine-specific sase config): when machine
overlays under the chezmoi source `dot_config/sase/` declare `memory.h1_title`, generate
the home agent instruction files as **chezmoi templates** whose H1 switches on
`.chezmoi.hostname`, so each machine's deployed files carry that machine's title. Then
declare titles for apollo and kellys_mbp in the chezmoi repo.

## Current Behavior (key code)

- `src/sase/amd/_config.py`
  - `_user_config_dir_for_home_root`: for the chezmoi home root, user config is read
    from `<root>/dot_config/sase/`.
  - `_user_config_paths` + `_load_user_amd_h1_title`: `sase.yml` then sorted
    `sase_*.yml`; last file that declares `memory.h1_title` wins; values validated by
    `_validate_amd_h1_title` (non-empty string or null).
  - `resolve_amd_h1_title`: project config wins, then user config; `None` title routes
    `plan_amd_memory_sync` to the minimal template.
- `src/sase/amd/_memory.py` — `plan_amd_memory_sync` resolves the title, renders via
  `_render_managed_agents` → `render_agents_template`, and validates structural anchors
  with `parse_amd_agents_document`.
- `src/sase/amd/_shared.py`
  - `provider_shim_specs`: provider shims are byte-for-byte copies of `AGENTS.md`. For
    chezmoi home roots the **preferred** file is currently static (`CLAUDE.md`) with
    `CLAUDE.md.tmpl` listed as a legacy path to migrate away from — the docstring says
    this is "Because the inlined `AGENTS.md` carries no template variables", which is
    exactly the assumption this feature removes.
  - `provider_shim_plan` / `apply_planned_delete` / `migrated_paths`: existing machinery
    that writes preferred files, deletes legacy files, and refuses to delete custom
    (non-shim, non-expected) content.
- `src/sase/main/init_memory/root_planning.py` — `memory_root_context` assembles
  expected files (the root `AGENTS.md` content comes from the AMD sync plan), then calls
  `provider_shim_plan(root, agents_content=final_agents_content(...))`.
- `src/sase/main/init_memory/root_planning_files.py` — `final_agents_content` and
  `validation_overlay_for_expected_files` look up the literal `root / "AGENTS.md"` path;
  `src/sase/amd/_memory.py::_existing_agents_long_descriptions` also reads
  `root / AGENTS.md` to carry over reference-memory descriptions.
- `src/sase/main/_init_chezmoi_ignore.py`
  - `ensure_machine_ignore_entry` writes the exact hostname-guard stanza
    `{{ if ne .chezmoi.hostname "<hostname>" }}\n<entry>\n{{ end }}` into the source
    `.chezmoiignore`; `chezmoi_target_entry` maps a source path to its target-relative
    entry (strips `dot_` prefixes).
- `src/sase/main/init_memory_handler.py` — for `use_chezmoi`, written/deleted home paths
  flow to `defer_chezmoi_paths` / `deploy_to_chezmoi`; deleted source paths map to live
  delete targets under `~`. In `src/sase/main/_init_chezmoi_deploy.py`,
  `_delete_live_targets` runs **before** `chezmoi apply --force`, so deleting a live
  target that a renamed source still manages is safe (apply recreates it).

Real chezmoi source state (linked repo `chezmoi`, under `home/`):

- `dot_config/sase/`: `sase.yml` (no `memory.h1_title`), `sase_athena.yml` (declares
  `id.machine_name: athena` + the athena title), `sase_apollo.yml` and
  `sase_kellys_mbp.yml` (only `id:` blocks).
- `.chezmoiignore` contains hostname guards pairing `sase_athena.yml` ↔ `athena`,
  `sase_apollo.yml` ↔ `apollo`, `sase_kellys_mbp.yml` ↔ `Kellys-MBP` (note: chezmoi
  hostname differs from the sase machine name here), plus an unrelated
  `.chezmoi.fqdnHostname` guard for `sase_work.yml`.
- `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, `QWEN.md`, `OPENCODE.md` are plain generated
  files with the athena H1.

## Design

**Trigger.** Templated output is produced only when both hold:

1. The root being initialized is a chezmoi home root (`_is_chezmoi_home_root`).
2. At least one _machine overlay_ in the source config dir — a `sase_*.yml` whose nested
   `id.machine_name` is valid (reuse the existing machine-name discovery used by config
   core rather than re-implementing) — declares `memory.h1_title`.

When the trigger does not fire, generation is byte-identical to today. Note the trigger
firing implies the current last-declared-wins resolution is non-`None`, so the managed
(non-minimal) render path is already taken; the pipeline renders with the current
resolved title and the H1 is swapped afterward (see Emission).

**Hostname mapping.** For each machine overlay declaring a title, resolve its chezmoi
hostname by parsing `.chezmoiignore` for the exact stanza shape that
`ensure_machine_ignore_entry` generates (`{{ if ne .chezmoi.hostname "<hostname>" }}` /
entry line(s) / `{{ end }}`), matching the overlay's `chezmoi_target_entry`. Fail
closed: a machine overlay that declares `memory.h1_title` but has no parseable
`.chezmoi.hostname` guard is a **blocker** with an actionable message (add the hostname
guard or run `sase config init` on that machine). Duplicate hostnames across
title-declaring overlays are also a blocker.

**Emission.** Post-process the fully rendered and validated `AGENTS.md` content:

1. Replace the H1 line (`# <title>`) with a single-line Go-template conditional so the
   rendered target still has exactly one H1 line:

   ```text
   {{ if eq .chezmoi.hostname "apollo" }}# <apollo title>{{ else if eq .chezmoi.hostname "athena" }}# <athena title>{{ else }}# <fallback>{{ end }}
   ```

   Branches are ordered deterministically (sorted by hostname). The `else` branch is the
   title the current `_load_user_amd_h1_title` resolution produces, so machines without
   their own guarded title keep exactly today's behavior.

2. Escape every literal `{{` elsewhere in the content as `{{ "{{" }}` so chezmoi renders
   the body back verbatim (a bare `}}` is already literal in Go templates). The current
   generated content contains no `{{`, but memory bodies are user content.

Provider shims remain byte-for-byte copies of the (now templated) `AGENTS.md` content.

**File naming and migration.** Templated content must live in `.tmpl` source files for
chezmoi to evaluate it:

- The root expected file becomes `AGENTS.md.tmpl`; plan a delete of the stale static
  `AGENTS.md`, guarded so only sase-managed content is deleted (it must parse with the
  `parse_amd_agents_document` structural anchors; otherwise emit a blocker rather than
  deleting user content).
- `provider_shim_specs` flips for templated chezmoi home roots: preferred `<name>.tmpl`,
  legacy static `<name>`. Reuse the existing `legacy_paths` + `migrated_paths` delete
  machinery so old full-copy static shims delete cleanly and custom content blocks with
  the existing "refusing to delete custom provider instruction content" safety. The
  non-templated chezmoi case and ordinary roots keep the current static-preferred
  behavior.
- Update the `root / "AGENTS.md"` lookups (`final_agents_content`,
  `validation_overlay_for_expected_files`, `_existing_agents_long_descriptions`, and the
  root-`AGENTS.md` exclusion in `agent_doc_shim_plans`) to consider `AGENTS.md.tmpl` at
  chezmoi home roots. For description carry-over, parsing the templated file is
  acceptable (the template action only occupies the H1 line and escaped bodies are
  rare), but unescape `{{ "{{" }}` before parsing if it is cheap.
- Deploy: the deleted static sources map to live delete targets (e.g. `~/AGENTS.md`)
  that the new `.tmpl` sources still manage. This is safe because live deletes run
  before `chezmoi apply` — verify this ordering holds on both the direct
  (`deploy_to_chezmoi`) and deferred (`defer_chezmoi_paths`) paths, and check whether
  `chezmoi_target_entry` callers need `.tmpl`-suffix stripping.

**No feature flag.** Per the SASE flag policy this is conditional new behavior, not a
deprecation: the static-generation branch remains the permanent behavior for non-chezmoi
roots and for configs with no machine-overlay titles, and nothing lands half-finished
behind this change. No beta or sunset flag is warranted.

**Stays in Python in this repo.** All existing `memory.h1_title` resolution and AMD
generation live in `sase.amd` / `sase.main.init_memory`; no other frontend renders these
files, so the Rust-core boundary is not crossed.

## Implementation Steps

1. **Guard parser.** In `src/sase/main/_init_chezmoi_ignore.py` (or a small sibling
   module), add a parser that returns `{target_entry: hostname}` for stanzas matching
   the generated hostname-guard shape in a `.chezmoiignore` text. Tolerate unrelated
   lines/stanzas (e.g. `.chezmoi.fqdnHostname` guards, plain entries) by ignoring them.
   Unit-test against the real-world shape above.

2. **Machine title resolution.** In `src/sase/amd/_config.py`, add a resolver (e.g.
   `resolve_chezmoi_machine_h1_titles(root)`) that, for a chezmoi home root, returns:
   sorted `(hostname, title)` pairs for machine overlays declaring `memory.h1_title`
   (validated with `_validate_amd_h1_title`), the fallback title from the existing
   `_load_user_amd_h1_title`, and blockers (missing guard, duplicate hostname, invalid
   title). Identify machine overlays with the same nested-`id.machine_name` rules config
   core uses for overlay selection.

3. **Template emission.** Add a pure helper (suggested:
   `src/sase/amd/_chezmoi_template.py`) that takes rendered agents content plus the
   `(hostname, title)` pairs and fallback, and returns the templated content (H1 swap +
   `{{` escaping). Unit-test escaping, branch ordering, single-H1-line output, and the
   else branch.

4. **Wire into planning.** In
   `src/sase/main/init_memory/root_planning.py::memory_root_context` (chezmoi home roots
   only, trigger per Design): transform the `AGENTS.md` expected file to
   `AGENTS.md.tmpl` with templated content; plan the guarded delete of stale static
   `AGENTS.md`; feed the templated content into `provider_shim_plan` with the
   `.tmpl`-preferred spec flip in `src/sase/amd/_shared.py::provider_shim_specs`.
   Surface resolver blockers through the existing `MemoryRootPlan.blockers` channel so
   `sase memory init` and `--check` report them.

5. **Existing-state reads and deploy details.** Apply the `AGENTS.md.tmpl` lookup
   updates and deploy/ignore-entry checks from Design ("File naming and migration").

6. **Tests.** Extend `tests/main/test_init_memory_chezmoi.py` and
   `tests/main/test_init_memory_managed_agents_shims.py`; add unit tests for steps 1–3.
   Cover at minimum: a fixture mirroring the real layout (base `sase.yml`, three machine
   overlays where only some declare titles, `.chezmoiignore` guards including an
   unrelated fqdn guard) asserting the emitted template and `.tmpl` renames plus
   static-file deletes; idempotence (a second run plans no changes); blocker cases
   (title without hostname guard; custom static shim content); and the untriggered
   chezmoi case remaining byte-identical to today. If the `chezmoi` binary is available,
   an optional `chezmoi execute-template`-based smoke test (skipped when missing) may
   verify per-hostname rendering.

7. **Docs.** Update `docs/configuration.md` (the `memory.h1_title` section's home-root
   paragraph and, if helpful, the Owner Identity chezmoi notes) and the relevant
   `sase memory init` docs (`docs/memory.md` / `docs/init.md`) to describe
   machine-specific titles, the `.tmpl` generation, and the guard requirement.

8. **Chezmoi repo config.** Open the linked repo with the `/sase_repo` skill
   (`sase repo open chezmoi -r "..."`) and edit under the printed path:
   - `home/dot_config/sase/sase_apollo.yml` — append:

     ```yaml
     memory:
       h1_title: "apollo - Bryan Bugyi's Rendezvous Server"
     ```

   - `home/dot_config/sase/sase_kellys_mbp.yml` — append:

     ```yaml
     memory:
       h1_title: "kellys_mbp - Kelly's MacBook Pro"
     ```

   (Titles follow the existing `athena - Bryan Bugyi's Home Server` pattern; apollo is
   the shared rendezvous host per `home/bin/executable_macscrot`. Adjust wording only if
   review feedback asks.) Do not run a live `sase memory init` from the agent run: it
   writes to the live chezmoi source outside the workspace and applies to the live home.
   The modified linked repo becomes a commit obligation handled at finalization.

9. **Verify.** Run `just check` in the sase repo before finishing (run `just install`
   first if the workspace virtualenv is stale), per the two-speed verification rule.

## Out of Scope

- Templating anything beyond the H1 title (this is deliberately the first increment of
  machine-specific chezmoi config support).
- Machine-specific titles for non-chezmoi (live) home roots — the `.chezmoiignore`
  guards already ensure only the matching overlay is deployed there.
- Regenerating the live chezmoi source: after this lands, the next `sase memory init`
  run on any machine (with the updated sase installed and the chezmoi repo pulled)
  produces `AGENTS.md.tmpl` + templated shims and deploys per-machine titles.
