# Plan: Rename `#research_swarm`'s `should_generate_image` input to `image`

## Goal

Rename the boolean `should_generate_image` input of the `#research_swarm` xprompt swarm
to `image`, so the image opt-in reads
`#research_swarm(prompt="A research topic", image=true)`. Behavior, type (`bool`),
default (`false`), and position in the input list stay the same.

## Context

- The swarm is defined in the **linked `sase-research-artifacts` repo**, not in the sase
  repo. Open it with `sase repo open sase-research-artifacts -r "<reason>"` and work
  only in the printed path. Read its `AGENTS.md` before editing.
- `should_generate_image` was added in the plugin commit
  `feat(research): make swarm infographic optional`, which came **after** the latest
  plugin release tag (`v0.2.0`). No published plugin version has ever carried
  `should_generate_image`. So this is a plain rename. Do NOT add a deprecated alias or
  compatibility shim.
- SASE's xprompt input binding (`src/sase/xprompt/input_binding.py`, `bind_input_args`)
  keeps unknown named arguments instead of rejecting them. After the rename, an old
  `should_generate_image=true` call will silently skip the image agent instead of
  failing. That is acceptable because the name was never released, but it means every
  in-tree caller must be updated. Nothing should still pass the old name after this
  change.
- The name `image` does not clash with anything in the template. `%id(image, …)` and
  `%model:@image` are literal directive text, not Jinja variables, and the plugin's
  `image` model alias in `default_config.yml` lives in a separate namespace.
- The sase repo's `.venv` has the released `sase-research-artifacts==0.2.0` installed
  from PyPI. That version predates the image opt-in, so it ignores both the old and the
  new argument name and always emits the image segment. So the sase-repo test keeps
  passing against the installed plugin when it switches to `image=true`, and it also
  passes against the renamed plugin once that is released and installed.
