## Remaining work (sase-core)

### 1. Classifier false positives (`classify.rs`)

Each of these misclassifies real code on SASE's own repositories:

- **Agent-context directory rules claim source code.**
  - `is_agent_context` matches `sase/memory` and `sase/macros` at any depth, and any
    path component named `skills`.
  - In sase this turns 75 Python files under `src/sase/memory/` and 6 under
    `src/sase/skills/` into agent context, so they drop out of code lines and language
    rows.
  - Fix: the directory-based agent-context rules (`sase/memory/`, `sase/macros/`,
    `skills/`) must never claim a file that would otherwise be classified as source or
    tests (a recognized programming language by extension or shebang). Prose, data, and
    template files in those trees stay agent context.
  - Agent instruction filenames (`AGENTS.md`, `CLAUDE.md`, and the others) stay agent
    context unconditionally.
  - The existing precedence still applies: generated/vendored exclusions and safety
    exclusions are checked first.
- **Generated path heuristic is too broad.**
  - `is_generated_path` excludes any path with a component named `snapshot`, `gen`, or
    `target`.
  - This excludes sase-core's own `crates/sase_core/src/project_stats/snapshot/*.rs` as
    generated.
  - Fix: remove `snapshot` (singular), `gen`, and `target` from the directory list. Keep
    `generated`, `autogenerated`, `snapshots`, `__snapshots__`, `golden(s)`, `dist`, and
    the filename suffix rules.
  - Explicit `linguist-generated` still overrides in both directions.
- **`.txt` is always prose.**
  - `requirements.txt`, `constraints.txt`, and `CMakeLists.txt` currently become docs.
  - Fix: a `.txt` file is docs only when it is neither a recognized config/data filename
    (`requirements*.txt`, `constraints*.txt`) nor a recognized language filename. Check
    what `source_language` returns for `CMakeLists.txt` and follow it.
- **Bump `PROJECT_STATS_CLASSIFIER_VERSION`** so cached snapshots rebuild and the query
  fingerprint changes.
- **Tests (`classify_tests.rs`):** add regression cases for every path above, including:
  - `src/sase/memory/foo.py` → source
  - `sase/memory/note.md` → agent_context
  - `.claude/skills/x/SKILL.md` → agent_context
  - `src/sase/skills/cli.py` → source
  - `tests/skills/test_x.py` → tests
  - `src/project_stats/snapshot/mod.rs` → source
  - `__snapshots__/a.snap` → generated
  - `requirements.txt` → config_data

  Keep the existing explicit-attribute and precedence tests green.

### 2. Committed-attribute session isolation (`snapshot/attributes.rs`)

`AttrSession::open` runs a bare `git init --bare` in the temporary directory with
ambient global/system config and templates. This causes three failures:

- A SHA-256 source repository gets a SHA-1 temporary repo, so `check-attr --source`
  fails and the whole Code snapshot is unavailable. `git::valid_oid` already accepts
  64-hex ids, so the rest of the pipeline supports SHA-256.
- A global `init.defaultObjectFormat=sha256` breaks every SHA-1 repo the same way.
- An `init.templateDir` that contains `info/attributes` leaks into the committed policy.

Fix:

- Read the source object format with `git rev-parse --show-object-format`.
- Initialize with `init --bare --template= --object-format=<format>`, under
  `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_SYSTEM=/dev/null`, and
  `GIT_CONFIG_NOSYSTEM=1`. Use the runner's `*_env` entry points, as `lookup` already
  does.
- Verify that an empty `--template=` really disables template copying on the installed
  Git.

Tests:

- A SHA-256 repository (`git init --object-format=sha256`, then commit) measures
  successfully with correct roles.
- A unit-level assertion that the session's init argv and env carry the isolation flags.
  Do not mutate process-global env in parallel tests.

### 3. Per-blob cache grows forever (`snapshot/` measurement + `snapshot/cache.rs`)

`measure_code_snapshot` seeds `blob_facts` from the previous cache entry and only ever
inserts. Facts for every blob version ever measured are carried forward and
re-persisted. The cache file, and its load cost on every new tip, therefore grow without
bound.

Fix: before persisting, keep only the facts whose OID is referenced by the current
tree's measured rows. Reuse across renames and moves in a single transition still works,
because pruning happens after measurement.

Test: after several successive content edits, the persisted entry holds facts only for
OIDs in the current tree. A warm result still equals a cold result, and the existing
blob-request seam still proves unchanged blobs are not reread.

### 4. Clone-disagreement handling (`code.rs`, `query.rs`)

The plan says to prefer a successfully measured clone, and to emit a disagreement issue
only when _successful_ clones disagree on the selected tip. The current code differs in
two ways:

- `measure_identity` computes `disagree` over all resolved clones, including clones
  whose measurement failed.
- On disagreement it overwrites the chosen clone's own issue (for example a partial
  issue) with `code_tip_disagreement`.

`query.rs` also discards the issues vector returned by `measure_identities`.

Fix:

- Compute disagreement from the distinct tips of successful measurements.
- Never drop the chosen clone's own issue. Surface the disagreement issue as well: in
  the response issues, and on every row of that identity whose row issue slot is free.
  The issue already names the chosen `canonical_path@tip`, so rows keep measurement
  provenance.
- Consume the `measure_identities` issues instead of discarding them, without
  duplicating issues already attached by `apply_snapshot`.
- Keep request-order independence and deterministic choice.

Tests in `code_query_tests.rs`:

- Agreeing clones emit no disagreement.
- Successful disagreeing clones emit it and keep the chosen clone's provenance.
- Where constructible, a failed clone at another tip does not trigger it.

### 5. Records gaps (`records.rs`, `records_tests.rs`, `../file_history/runner.rs`)

- **Missing tests.** The plan required these records tests; add them:
  - A merge history: the merge commit is counted, and min/max author time comes from
    nonmonotonic author dates across both parents.
  - Corrupted-cache recovery: a garbage cache file yields a fresh, complete measurement.
  - New-tip refresh: an entry cached at the old tip is not reused after a new commit.
- **User config can corrupt `git log` output.** `git log --format=%at` honours a user's
  `log.showSignature=true`, which puts gpg output on stdout.
  - The shared runner already pins config "so user config cannot change the output". Add
    `-c log.showSignature=false` to its pinned `-c` list.
  - Update the runner's doc comment and its argv/env unit test.
  - This also protects the history walker.

### 6. Code-quality cleanups caused by the epic

- Remove the six stale module-wide `#![allow(dead_code)]` lines in:
  - `classify.rs`
  - `records_cache.rs`
  - `snapshot/tree.rs`, `snapshot/attributes.rs`, `snapshot/blobs.rs`, and
    `snapshot/cache.rs`

  Every module now has a production caller. Delete, privatize, or `#[cfg(test)]` any
  item that rustc or clippy then reports as unused. Do not re-add a blanket allow.

- `snapshot/mod.rs` holds about 600 lines of logic, which breaks the facade convention.
  Move the measurement logic into a sibling module such as `snapshot/measure.rs`,
  leaving `mod.rs` with only `mod` and `use`/`pub(crate) use` lines. This is a pure
  move, with no behavior change beyond items 3 and 6.
- The blob read path computes `BlobEvidence::from_bytes(bytes)`, then calls
  `classify_file(..., Some(bytes))`, which scans the blob again. Pass the computed
  evidence through `classify_file_evidenced` instead, and delete `classify_file` if it
  becomes test-only or unused.
